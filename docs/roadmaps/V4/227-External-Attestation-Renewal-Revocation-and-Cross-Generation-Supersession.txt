Agentic AI V4 — Batch 227
External Attestation Renewal and Revocation Lifecycle, Cross-Generation Supersession, and Key-Cutoff Recovery-Gate Enforcement

Objective
Add a signed, challenge-confirmed lifecycle for Batch 226 external attestations. Renewal must create a new external attestation generation linked to its predecessor; revocation must be terminal and block current-decision use. Lifecycle events must participate in the independent external-attestation checkpoint snapshot.

Implementation
1. Add signed intent, renewed, revoked, superseded, and finalized events for external-attestation lifecycle operations.
2. Bind each operation to the current external attestation ID/digest/generation, ledger snapshot, challenge, reason digest, lifecycle generation, and signing-key lifecycle binding.
3. Require explicit confirmation and a bounded challenge TTL. Reject stale targets, conflicting operation IDs, duplicate pending operations, and renewals across a signing-key cutoff.
4. Renew by issuing a new Batch 226 external attestation whose binding includes the lifecycle-renewal event, then record signed predecessor/replacement supersession and finalization events.
5. Recover idempotently when interrupted after intent, renewal, new attestation issuance, supersession, revocation, or finalization.
6. Treat finalized revocation as terminal. A revoked external attestation cannot be renewed or re-issued; recovery-gate audits return `decision_blocked`.
7. Include lifecycle events in the independent external-attestation checkpoint snapshot and recovery-gate convergence status.
8. Add prepare/apply/audit application methods and HTTP routes.
