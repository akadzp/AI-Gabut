AI-GABUT — ROADMAP 04
STATE, STORAGE & PERSISTENCE
=============================

TUJUAN
------
Membangun boundary penyimpanan dan persistence generik AI-Gabut agar
state sistem dapat disimpan, diambil, divalidasi, dan dipulihkan secara
konsisten tanpa mengambil alih domain ownership subsystem lain.

ROADMAP
-------
01. Audit Existing State, Storage & Persistence
02. Define State & Storage Boundary
03. Define State Contracts
04. Build Core Storage Layer
05. Build State & Persistence Services
06. Validation
07. Definition of Done

DEFINITION OF DONE
------------------
Roadmap 04 dinyatakan selesai apabila:

1. Core storage mempunyai contract dan API generik.
2. Record storage mendukung CRUD, atomic write, version, etag,
   expected-version conflict detection, dan safe key/path validation.
3. Object storage mendukung byte storage, atomic write, size metadata,
   etag, dan safe key/path validation.
4. Storage errors menggunakan contract terstruktur.
5. State Persistence Service tersedia sebagai facade generik.
6. State mempunyai scope terisolasi: sessions, memories, executions, runtime.
7. State facade tidak bergantung pada Agent Engine, application,
   connector, atau product identity.
8. Public storage export menyediakan createStateService.
9. Test storage record/object terintegrasi ke npm test.
10. Test state service terintegrasi ke npm test.
11. Architecture boundary tidak dilanggar.
12. Validation source menunjukkan tidak ada dependency terlarang
    dari storage ke Agent Engine.
13. Implementasi tetap berada di core/storage dan tidak memindahkan
    ownership domain dari Workspace, Agent Engine reliability,
    Security, Tasks, atau Connectors.
