Batch 155 — Policy-Binding Audit-Chain External Checkpointing, Compaction Manifest Approval Workflow, and Cache Invalidation Race/Freshness Tests

- Added a dedicated external checkpoint trust domain for the combined cross-domain policy-binding audit chain. The source snapshot binds event IDs, domains, sequences, event digests, previous-event links, challenge digests, resulting anchor digests, target policy digests, and timestamps.
- Added explicit enrollment, status, audit, and reconciliation APIs for the policy-binding audit-chain checkpoint. Reconciliation advances exactly one provable event and rejects source-chain tampering, unhealthy local audits, and multi-event jumps. The new provider is included in provider-instance and endpoint independence checks.
- Added a challenge-bound approval workflow for provider-baseline receipt compaction manifests. Approval binds the manifest digest, source fingerprint, and checkpoint sequence/digest, revalidates source state before application, supports idempotent recovery, and audits duplicate or tampered approvals. Approval is for controlled review only: no compaction, deletion, or automatic destructive action is performed.
- Hardened retention-decision revalidation caching with a bounded cache age and checkpoint freshness deadline. Cache reuse now performs a second fingerprint capture; a source, checkpoint, policy, or retention-state change during evaluation returns `revalidation_race_detected` and is not cached.
- Retention-decision currentness now requires a fresh, current external retention-review checkpoint when configured. A configured policy-binding audit-chain checkpoint is also fingerprinted and must be anchored and fresh; pre-enrollment history remains explicitly marked as unproven.
- Added authenticated application APIs and HTTP routes for policy-binding audit-chain checkpoint lifecycle and compaction-manifest approval/audit.
