V4 — GIT / CHANGE / PULL REQUEST WORKFLOW

Tujuan: membawa Work yang sudah tervalidasi menuju external change workflow yang governed.

Implementation:
- provider-neutral Git workflow state di application layer
- GitHub branch preparation
- commit tree/blob/ref orchestration melalui GitHub connector
- commit evidence dan Work/Change linkage
- pull request creation dan metadata/evidence
- git_commit dan git_push tetap melalui security approval authority
- credential tetap berada di connection/credential boundary

Boundary:
- Git-specific API tetap di connector;
- orchestration tetap di V4 work-git;
- approval tetap melalui security authority;
- external outcomes tersimpan sebagai evidence pada workflow.

DoD: Work dapat dibawa dari Change menuju branch, commit, dan Pull Request GitHub dengan approval serta evidence yang dapat diverifikasi.
