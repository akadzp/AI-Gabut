V4 — BATCH 01 — WORK & TASK MODEL

STATUS
======
IMPLEMENTED — pending local repository validation.

PURPOSE
=======
Work menjadi resource product-level utama untuk pekerjaan user. Work tidak
menggantikan session, task, atau execution; Work mengorkestrasi referensi
ketiganya sebagai satu unit pekerjaan yang dapat dilihat dan dikendalikan.

BOUNDARY
========
V4 application/work layer owns:
- work identity
- objective
- project/workspace context reference
- work lifecycle
- priority
- references to tasks, executions, changes, evidence, approvals
- result/outcome

V2/V3 remain owners of:
- Agent Engine execution capability
- security/approval authority
- storage primitives
- GitHub connector and external provider identity
- workspace and connection foundation

CONTRACT
========
Work shape:
- id
- ownerId
- projectId|null
- workspaceId|null
- objective
- context
- plan|null
- taskIds[]
- executionIds[]
- changeIds[]
- evidenceIds[]
- approvalIds[]
- result|null
- state
- priority
- createdAt
- updatedAt
- startedAt|null
- finishedAt|null
- cancelledAt|null

Lifecycle:
draft → ready → running
running → waiting_approval | paused | completed | failed | cancelled | stopped
waiting_approval → running | paused | cancelled | failed
paused → ready | running | cancelled | stopped
draft → ready | cancelled
ready → running | cancelled

Terminal states:
- completed
- failed
- cancelled
- stopped

Terminal Work cannot be mutated or transitioned again.

OWNERSHIP
=========
All Work operations are owner-scoped. A user cannot read, mutate, cancel,
or attach references to another user's Work.

RESOURCE SEPARATION
===================
Task and Execution remain independent resources. Work stores their IDs and
does not copy their lifecycle into the Work object.

REFERENCE MODEL
===============
Work may reference:
- task
- execution
- change
- evidence
- approval

References are explicit and append-only at this batch. Provider-specific
objects are not embedded as Work identity.

API SURFACE
===========
Authenticated Agentic API:
- POST   /api/agentic/works
- GET    /api/agentic/works
- GET    /api/agentic/works/:id
- PATCH  /api/agentic/works/:id
- POST   /api/agentic/works/:id/transition
- POST   /api/agentic/works/:id/cancel
- POST   /api/agentic/works/:id/tasks/:taskId
- POST   /api/agentic/works/:id/executions/:executionId
- POST   /api/agentic/works/:id/references/:kind/:referenceId

AI + GITHUB
===========
Work may carry workspace/project context but does not make GitHub its
identity. GitHub remains reachable through the V3 workspace/connection/
connector boundary.

- task/execution separation
