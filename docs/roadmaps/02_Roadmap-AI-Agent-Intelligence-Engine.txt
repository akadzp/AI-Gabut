ROADMAP 02 — AI / AGENT INTELLIGENCE ENGINE

PURPOSE
Build the generic Agent Engine boundary and intelligence lifecycle used by
multiple application identities without coupling the engine to a product,
connector, HTTP server, or concrete infrastructure implementation.

BOUNDARY
The engine owns task understanding, goal management, context orchestration,
reasoning, decomposition, planning, execution planning, replanning, model
routing, tool lifecycle coordination, specialist orchestration, execution
checkpoint coordination, reliability coordination, evaluation, and
interpretation of model/tool results.

The engine consumes model providers, context/state services, capability/tool
services, security authorization, workspace/task services, and connectors.
It does not own filesystem, terminal, Git, connector, persistence, HTTP,
security policy, or product identity implementations.

STEP 07 DEFINITION OF DONE
The roadmap is complete because:
- The engine boundary is explicit and reusable by multiple application identities.
- External consumers use core/agent-engine/index.js as the public engine surface.
- Internal context, reasoning, model, tool, specialist, evaluation, and reliability modules remain implementation details behind that surface.
- Reliability provides checkpoint/resume, execution locking, timeout control, and observable metrics.
- Evaluation provides observable trajectory scoring, regression evaluation, async evaluation, and failure analysis.
- Architecture validation rejects direct external imports of Agent Engine internals.
- Syntax and source-level validation pass for the current 69-JavaScript-file tree.
- Historical V1 milestone checks are documented separately where they still assume the old backend layout.
- No product identity is embedded into the generic Agent Engine.
