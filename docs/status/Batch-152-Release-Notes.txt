Batch 152 — Audit-Attestation Checkpoint Freshness/Retention Enforcement, Provider-Baseline Replay-Resistant Transition Receipts, and Retention-Review External Decision Reconciliation

Implemented
-----------
- Added freshness enforcement at the cross-domain audit-attestation decision boundary. Verification distinguishes historical signature validity from current usability; an aged checkpoint cannot authorize current use until an explicit refresh appends a digest-linked checkpoint over an unchanged, verified source snapshot. Excessive future clock skew and invalid timestamps fail closed.
- Added retention classification for signed audit attestations. Evidence beyond the configured retention window requires an explicit, digest-bound review. A `retain` decision only restores eligibility after the decision's external checkpoint is current when that trust domain is enabled; `escalate`, pending approval, invalid evidence, and unreviewed overdue evidence remain unusable for current decisions. No evidence is automatically deleted.
- Added deterministic provider-baseline transition receipts binding owner, domain, revision, source challenge, prepared challenge digest, previous baseline digest, resulting baseline digest, provider identity/contract fingerprints, source conformance report, previous receipt digest, and issue time. Receipt chains are audited for tampering, missing/orphan receipts, gaps, and invalid linkage. Legacy transitions without receipts remain explicitly distinguishable; the first receipt after legacy history marks history as unproven.
- Added resumable receipt finalization for an interruption after the baseline is stored and its receipt is written but before the completed challenge is finalized. Recovery is permitted only when the current baseline and prepared challenge exactly match the receipt.
- Added one-transition-only retention-review checkpoint reconciliation. A pending decision can advance the external checkpoint only when removing exactly one approval recreates the prior anchored snapshot digest. Multi-decision jumps, same-count rewrites, invalid replay guards, and unprovable continuity are rejected.
- Added an authenticated API/HTTP route for provider-baseline transition-receipt audits. Existing audit-attestation checkpoint status and reconciliation APIs now expose freshness and refresh behavior.
