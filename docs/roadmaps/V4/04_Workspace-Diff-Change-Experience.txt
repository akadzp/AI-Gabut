V4 Batch 04 — Workspace, Diff & Change Experience

Audit result:
V2 already contains core/workspace/change-system.js. Therefore V4 must NOT
create a competing planner/editor/reviewer. The V4 Change resource is an
owner-scoped Work envelope around the V2 Change foundation.

V4 owns:
- Work/Workspace relationship
- owner scope
- human vs agent origin
- execution provenance
- bounded snapshots
- review/rollback evidence exposed to the Work UI

V2 owns:
- change planning
- workspace file access
- safe editing and stale-write protection
- change review
- V2 change lifecycle

V3 Workspace remains repository/branch context. It is not silently treated as
a writable local checkout.

DoD:
1. Durable owner-scoped Change envelope.
2. Mandatory Work -> Workspace binding.
3. v2ChangeId links to the V2 change foundation.
4. Baseline SHA-256 and bounded snapshot are persisted.
5. Edit/review delegate to V2.
6. Rollback is conflict-safe.
7. Authenticated list/get/create/capture/edit/review/rollback/close API.
8. Frontend Change review surface.
9. Focused tests registered in test:agentic.
10. Full npm test passes before Batch 04 is declared Done.

Implementation handover:
- Batch 04 source changes are delivered separately as a ZIP.
- npm test remains the user-side validation gate.
