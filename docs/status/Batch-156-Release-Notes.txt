Batch 156 — Policy-Binding Audit Checkpoint Freshness Attestation, Manifest Approval Revocation/Supersession, and Concurrent Revalidation Consistency

- Added signed Ed25519 freshness attestations for policy-binding audit checkpoints. Attestations bind checkpoint/audit snapshots and the active freshness policy digest inputs (maximum age and future-skew tolerance). Verification distinguishes historical signature validity, currentness, and usability for current decisions. A checkpoint with unproven pre-enrollment history may be signed as historical evidence, but is explicitly marked history_unproven and cannot authorize a current decision.
- Added explicit challenge-bound revocation for provider-baseline receipt compaction-manifest approvals. Revocation is available only after the manifest is no longer current/eligible, binds the exact observed source state, and fails if that state changes or becomes eligible again before application. Approval records remain immutable; audits report current approvals, superseded approvals, and revoked approvals separately. No compaction or deletion is performed.
- Added per-owner/per-approval single-flight revalidation so overlapping requests share one result and cannot independently publish conflicting cache outcomes. Cache audit now reports coalesced and in-flight revalidation counts. Freshness deadline expiry is classified as external_checkpoint_pending rather than being misreported as a source race; actual generation conflicts still fail closed as revalidation_race_detected and are not cached.
- Added authenticated API methods and HTTP routes for checkpoint freshness attestation creation/verification/audit and manifest-approval revocation challenges/application/audit. Required attestation mode rejects startup unless an external signer, key ID, and matching trusted Ed25519 public key are configured.
- Added regression coverage for signed historical/current attestation behavior, freshness-policy drift, manifest supersession and explicit revocation, stale revocation challenges, concurrent revalidation coalescing, and required signer configuration.
