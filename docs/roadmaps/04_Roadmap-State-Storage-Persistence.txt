STEP 01 — AUDIT FINDINGS
------------------------
Existing state/storage is currently fragmented rather than provided by
a unified persistence boundary.

Existing persistent behavior:
- Agent execution reliability checkpoints are persisted as JSON files
  under `.ai-gabut/executions` by `core/agent-engine/reliability/runtime.js`.
- Workspace files are persisted directly through `core/workspace/manager.js`
  against the workspace root.
- Project structure reserves `data/` for databases, archive, cache,
  agent state, objects, vectors, workspaces, and files.
- Project structure reserves `runtime/` for agent checkpoints,
  executions, sessions, cache, and tasks.

Existing in-memory state:
- Agent sessions use a process-local Map.
- Agent memory uses process-local state.
- Security approvals use process-local state.
- Reliability execution locks and metrics use process-local state.
- Several intelligence/indexing caches are process-local.

Existing placeholders:
- `core/storage/` contains category directories but no storage contract
  or implementation.
- `core/sync/` contains category directories and a README but no sync
  implementation.
- `core/tasks/` contains category directories but no task persistence
  implementation.
- `data/*` and `runtime/*` contain structural placeholders.

IMPORTANT BOUNDARY FINDINGS
---------------------------
1. Workspace persistence is currently implemented directly by the
   workspace subsystem. Roadmap 04 must not move workspace ownership
   into storage merely for abstraction's sake.

2. Reliability currently owns execution checkpoint persistence because
   execution recovery is part of Agent Engine reliability. Roadmap 04
   should introduce storage contracts without breaking this behavior.

3. Storage must be an infrastructure service. It must not own product
   identity, reasoning, authorization policy, connector logic, or HTTP.

4. Runtime state and persistent state must remain distinct. A process-local
   Map is not automatically equivalent to durable state.

5. Secret material must never become a generic persisted object merely
   because a storage service exists. Roadmap 03 security controls remain
   authoritative.

6. Workspace files, object/blob data, structured records, vector data,
   cache, snapshots, and execution state have different lifecycle and
   consistency requirements and should not be forced into one primitive.

CURRENT GAPS
------------
- No canonical storage interface.
- No canonical state record/version contract.
- No repository/database abstraction.
- No object/blob abstraction.
- No snapshot contract.
- No transaction/idempotency contract.
- No persistence lifecycle/retention abstraction.
- No indexing abstraction.
- No unified cache contract.
- Runtime paths and data paths are documented but not centrally governed.

STEP 01 DECISION
----------------
No production source changes are made in the audit step.
The next step must define ownership and contracts before implementation.
